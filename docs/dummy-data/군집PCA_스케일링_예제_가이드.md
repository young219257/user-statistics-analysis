# 군집·PCA 스케일링 예제 데이터

단위가 다른 변수(소득은 수천, 나머지는 0~30)를 스케일링하지 않고 군집·PCA를 하면 **소득만으로 결과가 정해진다**는 것을 화면에서 확인하기 위한 데이터입니다.

| 파일 | 설명 |
|---|---|
| `군집PCA_스케일링_예제데이터.xlsx` | 시트 1개(`data`), 300행 × 6열. 1단계에서 올리는 파일 |
| `군집PCA_스케일링_예제데이터.csv` | 같은 내용의 CSV(UTF-8 BOM) |
| `군집PCA_정답_고객유형.csv` | 고객마다 실제 유형(충성 / 일반 / 이탈위험). **데이터 파일에는 넣지 않았습니다.** 넣으면 변수 후보에 들어가 정답을 입력으로 쓰게 되기 때문입니다. |

## 데이터 구성

고객 300명, 실제로는 세 유형이 100명씩 섞여 있습니다.

| 열 | 범위 | 군집을 가르는 열인가 |
|---|---|---|
| `customer_id` | C0001~C0300 | 식별자 (변수 후보에서 제외됨) |
| `visits_per_month` | 0~29 | **예** — 충성 약 20, 일반 약 10, 이탈위험 약 3 |
| `satisfaction` | 1~5 | **예** — 충성 약 4.5, 일반 약 3.4, 이탈위험 약 2.2 |
| `spend_ratio` | 0~1 | **예** — 충성 약 0.70, 일반 약 0.45, 이탈위험 약 0.20 |
| `age` | 13~63 | 아니오 (유형과 무관한 잡음) |
| `income_manwon` | 1,079~10,087 (만원) | 아니오 (유형과 무관, **값의 범위가 큼**) |

→ 실제 유형을 가르는 것은 앞의 세 열인데, 값의 범위가 가장 큰 `income_manwon`이 거리 계산을 지배합니다.

## 따라 하기

1. 1단계에서 xlsx를 올리고, 2단계에서 아무 이상치 기법을 실행합니다.
2. **A. 스케일링 안 함**: 2단계 규칙은 그대로 두고 3단계로 갑니다.
   **B. 스케일링 함**: 2단계 "3. 특성 스케일링"에서 `표준화 (Standard)`를 고르고 3단계로 갑니다.
3. 4단계에서 **K-평균 군집**(변수 5개 전체, 군집 수 3, 자동 탐색 해제) 또는 **주성분분석**을 고르고 실행합니다.
4. 4-2 리포트에서 아래 값과 비교합니다.

## 4단계 화면 문구 확인

군집·PCA를 고르면 실행 버튼 위에 스케일링 안내가 나옵니다.

| 2단계에서 | 4단계에 나오는 안내 |
|---|---|
| 스케일링 안 함 | 주황 ⚠ **"단위가 다른 변수는 먼저 스케일링하세요"** + 설명 + **2단계에서 스케일링 지정하기**(2단계로 이동) |
| 표준화 등 적용 | 남색 ⓘ **"2단계에서 표준화(Standard)를 적용한 데이터입니다"** |

군집·PCA가 아닌 기법(회귀 등)에는 이 안내가 나오지 않습니다. 4단계에는 더 이상 "표준화 후 분석" 선택이 없습니다. 스케일링은 2단계에서만 정합니다.

## 기대 결과 (화면에서 직접 확인한 값)

### K-평균 군집 (k = 3)

| 항목 | A. 스케일링 안 함 | B. 표준화 적용 |
|---|---|---|
| 군집 크기 | 81 / 85 / 134 (고르지 않음) | 98 / 101 / 101 (실제 100명씩에 가까움) |
| 군집별 평균 소득(만원) | 3,046 / 5,064 / 7,145 (**소득으로 갈림**) | 5,027 / 5,078 / 5,225 (소득과 무관) |
| 실제 유형과의 일치도(ARI) | −0.004 (거의 무관) | **0.96** (거의 일치) |
| 실루엣 | **0.544** | 0.272 |
| Calinski-Harabasz | 708.5 | 163.0 |
| Davies-Bouldin | 0.546 | 1.457 |
| 군집 간 분산 비율 | 82.7% | 52.3% |
| Inertia | 146,145,484 | 715.1 |

> **주의**: 스케일링하지 않은 쪽의 실루엣·군집 간 분산 비율이 더 "좋게" 보입니다. 소득 하나만 기준으로 갈랐기 때문에 수치가 높게 나오지만 의미 있는 군집이 아닙니다. 지표만 보고 판단하면 틀립니다.

### 주성분분석

| 항목 | A. 스케일링 안 함 | B. 표준화 적용 |
|---|---|---|
| 제1주성분 설명률 | **99.99%** | 54.47% |
| 제2주성분 설명률 / 누적 | 0.00% / 100% | 20.45% / 74.92% |
| 제1주성분 적재값 | `income_manwon` 1.000, 나머지 거의 0 | `visits_per_month` .580, `satisfaction` .570, `spend_ratio` .581, `age`·`income` 거의 0 |

→ 스케일링하지 않으면 제1주성분이 사실상 소득 하나이고, 표준화하면 실제 군집을 가르는 세 변수가 함께 묶입니다.

## 서버 상태에 따라 달라지는 것

- **지금 테스트 서버**: 4단계에서 스케일링을 따로 지정하지 않으면 조용히 원 단위로 분석하고, 경고는 나오지 않습니다. 위 값은 이 서버에서 확인한 것입니다.
- **서버 계획(이슈 #32)**: 2단계에서 스케일링하지 않은 데이터를 군집·PCA로 분석하면 원 단위로 분석하고 **결과에 경고를 남깁니다.** 서버가 배포되면 A 결과 화면에 그 경고가 추가로 보여야 합니다. 값은 같습니다.
- 그래서 이 화면의 스케일링 선택은 **2단계에서 하는 것**이 유일하게 확실한 방법입니다.
