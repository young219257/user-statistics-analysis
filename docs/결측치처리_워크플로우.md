# 화면 결측치 처리 워크플로우

이용자통계분석 화면(STEP1~2)에서 결측치를 다루는 흐름과 한계, 개선 방향을 정리한 문서입니다.
기준일: 2026-11-11 · 화면 파일: `ot_dim_dmmbm03_m01.js`(반입), `ot_dim_dmmbm03_m02.js`(품질·전처리)

## 1. 현재 흐름

결측치 처리는 두 단계로 나뉩니다.

| 단계 | 하는 일 | 화면 |
| --- | --- | --- |
| STEP1 반입 | **무엇을 결측으로 볼지** 정한다 | 선택한 데이터 표의 「결측으로 처리할 값」 열 |
| STEP2 품질·전처리 | **결측을 어떻게 채울지** 정한다 | 「1. 결측치 정제」 전략 선택 |

### 1-1. STEP1 반입 — 결측으로 볼 값 지정

1. 파일(CSV, XLSX)을 올린다. 서버는 빈 칸, `NA`, `null` 같은 값만 결측으로 인식한다.
2. `999`, `-1`, `-` 같은 값은 일반 값으로 반입된다.
3. 이 값을 결측으로 바꾸려면 「선택한 데이터」 표의 **결측으로 처리할 값** 열에 열별로 쉼표로 적는다.
   - 이 열은 **반입된 데이터셋(파일)을 선택했을 때만** 보인다. 데이터관리카드, 결합 결과, 결합된 데이터셋에서는 보이지 않는다.
4. **결측 값 적용**을 누르면 입력한 값을 `{열: [값]}` 형태의 `na_values`로 담아 **같은 파일을 다시 반입**하고, 이전 데이터셋은 지운다.
   - 이 화면에서 방금 올린 파일은 화면이 기억하고 있어 바로 재반입한다.
   - 이전에 반입한 데이터셋은 원본이 없으므로, 적용할 때 **원본 파일을 한 번 선택**한다. 다른 이름의 파일을 고르면 확인창이 뜬다.
5. 서버가 돌려주는 `warnings`는 업로드 영역 아래 노란 안내로 보여 준다.

> 재반입이 필요한 이유: 서버가 결측 값을 **업로드 때만** 받는다. 반입 후에는 원본을 지우고 Parquet만 보관한다.

### 1-2. STEP2 품질·전처리 — 결측 처리 전략

1. 결측 현황 카드가 결측 건수와 비율을 보여 준다.
2. 「1. 결측치 정제」에서 전략을 고른다.
   - 처리 안 함(기본), 중앙값으로 대체, 평균값으로 대체, 최빈값으로 대체, 결측 행 제거
3. 전략을 고르면 `/preprocess`로 서버에 보내 새 결과를 받고, STEP3 이후는 그 결과로 진행한다.
4. 아무 전략도 고르지 않으면 서버를 호출하지 않는다.

## 2. 전체 흐름도

```
파일 선택
  │
  ▼
[서버] 파싱 · 빈 칸/NA/null 만 결측 처리  ──▶ warnings 안내
  │
  ▼
STEP1 표: 열별 「결측으로 처리할 값」 입력 (반입된 데이터셋만)
  │
  ├─ (입력 없음) ──────────────────────────────┐
  │                                              │
  ▼                                              │
[결측 값 적용] → 같은 파일을 na_values 로 재반입    │
  (원본 없으면 파일 1회 선택, 이전 데이터셋 삭제)   │
  │                                              │
  ▼                                              ▼
STEP2: 결측 현황 확인 → 「결측치 정제」 전략 선택 → /preprocess
  │
  ▼
STEP3 이후 (전처리된 데이터로 진행)
```

## 3. 현재 흐름의 한계

| 구분 | 내용 |
| --- | --- |
| 의심 값 발견 | 서버가 `suspected_missing`(응답 없음 코드로 보이는 값)을 주지만 화면은 아직 쓰지 않는다. 사용자가 `999` 같은 값을 직접 알아서 적어야 한다 |
| 재반입 | 값을 적을 때마다 파일을 다시 올린다. 이전 반입 데이터셋은 원본 파일을 다시 골라야 한다 |
| 전략 범위 | 전략은 모든 열에 같이 적용된다. 열마다 다른 전략은 쓸 수 없다 |
| 탐지 한계 | 서버는 나이 20~60 열의 99처럼 나머지 값과 충분히 떨어지지 않는 코드는 탐지하지 않는다 |

## 4. 서버 현황과 의존

| 항목 | 상태 |
| --- | --- |
| 열별 `na_values` (`{열:[값]}`) | 서버 master에 반영됨(이슈 #21, PR #22). testlab은 아직 이전 빌드라 재배포 전에는 화면에서 적용되지 않을 수 있음 |
| 프로파일 `suspected_missing` | 서버 master에 반영됨. 화면 미연동 |
| 반입 후 열별 결측 값 지정 API | **미반영** — 서버 이슈 #26으로 요청함 |
| 혼합 타입 열 XLSX 반입 실패 | 서버 master에서 문자열 열로 반입하도록 수정됨(#19) |

## 5. 줄이는 방향 (제안)

1. **의심 값 미리 채우기**: 반입 직후 `suspected_missing`을 표에 「결측으로 처리하시겠어요?」 형태로 미리 채워 준다. 사용자는 확인만 한다. (지금 서버로도 가능)
2. **재반입 제거**: 서버 #26이 반영되면 파일 재선택 없이 바로 적용한다.
3. 1~2가 되면 사용자가 하는 일은 **반입 → 의심 값 확인 → 전략 선택**의 세 단계로 줄어든다.

| | 현재 | 개선 후 |
| --- | --- | --- |
| 값 찾기 | 사용자가 직접 | 서버가 후보 제시 |
| 값 적용 | 파일 재반입 | 즉시 적용(#26 이후) |
| 사용자 작업 | 값 입력 → 적용 → 재반입 → 전략 선택 | 후보 확인 → 전략 선택 |
